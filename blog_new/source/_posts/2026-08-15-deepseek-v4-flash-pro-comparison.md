# 同一个任务丢给 DeepSeek 两款新模型：贵 3 倍的 V4-Pro 值不值？

DeepSeek 开源 Harness（dsh）的那天晚上，我做了个小实验：把同一个写作任务，分别丢给它家最新的两个模型——deepseek-v4-flash 和 deepseek-v4-pro。

任务很简单：写一篇介绍 dsh 的技术博客。两个模型拿到了同样的条件——同样的任务描述、同样的背景材料（包括"我之前拆过 Claude Code 源码"这个作者视角）、同样的发布要求（发在我的技术博客上）。

两个模型各交了一篇 3000 字上下的稿子。这篇文章把两篇稿子的关键段落原样贴出来，对比它们的真实差距，再对着官方定价算一笔账：贵 3 倍的 V4-Pro，到底值不值。

<!-- more -->

## 先看 V4-Flash 的稿子

Flash 稿的完成度出乎意料。它最亮的是开头，一段话把 Harness 这个陌生概念讲透了：

> Harness 这个词原意是马具、挽具，引申义是"把马套上车的那套装置"。
>
> 用在 Agent 上很贴切：模型是那匹马，Harness 是把马的力气真正转化成"干活"的整套装置。

全文是标准的科普文走法：先用比喻建立概念，再解释为什么 Agent 需要这层壳，然后把 dsh 的口号"一切皆插件"（Everything is a Plugin）拆成三层意义——可替换、可组合、可自修改：

> **可自修改。** 既然一切皆插件，Agent 理论上可以在运行时管理自己的插件——加插件、换插件、改自己的行为。很多报道把它称为"自进化软件"的雏形。

结尾还给了一个大局判断：

> 当头部模型能力越来越接近，Agent 的差距正在从"模型"转移到"壳"上。

这个判断和我拆 Claude Code 源码时的体感完全一致。便宜的那位模型，判断力没打折。

但往下读，问题也来了。通篇没有一条可以运行的命令，没有出现任何版本号，对底层框架 Cordis 只有一句带过——"底层跑在一个叫 Cordis 的插件内核上"。更让我皱眉的是这句：

> 发布当天 GitHub 就冲了好几万 star。

我在官方发布页和仓库里都找不到这个数字的出处。同一段里还有"社区也有人做了 Electron 桌面壳"，同样查无实据。这些句子读起来生动，但发出去之前，每个数字都得人工核一遍。

## 再看 V4-Pro 的稿子

Pro 稿走的是完全另一条路。它没花力气打比方，上来就把 dsh 的组织方式讲到了配置层：

> - **profile**：一个命名好的组合，存在 Harness 的 home 目录里。它声明自己叠加哪些 bundle、装了哪些树外插件，还保存一份你自己的 `cordis.patch.yml`。
> - **bundle**：Cordis 配置行 + 它要挂载的代码的一种分发格式。`dsh-base` 是每个 profile 的第一层，装的是模型适配器、工具、持久化、沙箱、审批策略这些最基础的东西。

然后是三个官方文档级的细节，一个比一个硬。

第一，session 日志的设计原则：

> 它的 session 日志是一条只追加的事件流，模型看到的上下文必须能从这条日志重建——用官方的话说，「model-visible means logged」（模型可见即已记录）。

第二，工具调用不是裸奔，要过 `tools/pre-execute → tools/execute → tools/post-execute` 三段管道；权限审批是运行时的一等公民。

第三，版本身份。它连 npm 包的版本号都去看了，还给出了正确解读：

> npm 上的版本号是 `0.1.0-rc.6`——rc 是 release candidate，不是 stable。

上手命令拿来就能跑：

```sh
npx @deepseek-ai/dsh web
```

默认端口 3080；headless 模式不开任何监听端口，跑完退出，正常退出码 0、出错 1——这些细节全部能在官方文档里对上。文末它还老实交代了一句："未做深度实测"。

Pro 稿的短板在另一头：门槛高。前两节就抛出 profile、bundle、seam、事件流这些概念，没有比喻垫着，普通读者很可能撑不到第三节。

## 四回合，各赢一半

| 回合 | 谁赢 | 一句话理由 |
| --- | --- | --- |
| 谁真读过文档 | Pro | 命令、端口、版本号、seam 三角色，细节全能对到官方文档；Flash 更像读了报道之后写的综述 |
| 谁更敢编 | Pro | Flash 的"几万 star"查无出处；Pro 最冒险的表述是把官方警告原样大写引用 |
| 谁更好读 | Flash | "马与挽具"一段顶 Pro 一整节；Pro 判断准但门槛高 |
| 谁适合直接发 | Flash | front matter 完整、延伸阅读给的是站内链接，说明它理解了"这是发在我博客上的文章" |

我的判词：**Flash 是合格的科普作者，Pro 是靠谱的技术编辑。** 真要发一篇，最好的做法是让 Pro 写主体，把 Flash 的开头嫁接过去。

也要说清楚局限：这是一次写作任务的单点实测，样本量是一，替代不了 benchmark。但"便宜的模型更敢编"这个现象，这次又应验了——用 Flash 的产出，事实核查这一步省不掉。

## 价格：Pro 全面是 Flash 的 3 倍

效果说完了，说钱。下面是 DeepSeek 官方定价页的数据，单位是元/百万 tokens：

| 模型 | 时段 | 输入（缓存命中） | 输入（缓存未命中） | 输出 |
| --- | --- | --- | --- | --- |
| v4-flash | 空闲 | 0.05 | 1.5 | 4.5 |
| v4-flash | 高峰 | 0.10 | 3.0 | 9.0 |
| v4-pro | 空闲 | 0.15 | 4.5 | 13.5 |
| v4-pro | 高峰 | 0.30 | 9.0 | 27.0 |

两个值得注意的点。

**第一，Pro 对 Flash 是全维度 3 倍价**——缓存、输入、输出都是整整 3 倍，没有哪一项手下留情。

**第二，这套价格 2026 年 8 月 17 日 0 点才生效。** DeepSeek 刚切换到峰谷分时定价：高峰时段（北京时间 9:00–12:00、14:00–18:00）全价，其余时段半价。此次调价相对旧价涨幅明显。如果你走的是第三方托管（OpenRouter、DeepInfra 等），报价和官网差异不小，下单前自己再对一遍。

## 算一笔账：一篇文章，最贵四毛一

价格表看着抽象，直接换算成"写一篇文章要花多少钱"。

按一次典型写作估算：给模型喂 3 万 tokens 的参考资料（按缓存未命中算），它输出 5 千 tokens 的成稿：

| 时段 | V4-Flash | V4-Pro |
| --- | --- | --- |
| 空闲 | 0.07 元 | 0.20 元 |
| 高峰 | 0.14 元 | 0.41 元 |

（估算口径：纯 API 调用，不含平台加价；实际有缓存命中会更便宜。）

也就是说：**用最贵的组合（Pro + 高峰），一篇 3000 字技术文的成本是四毛一；最便宜的组合（Flash + 空闲）只要七分钱。** 写作场景下，Pro 贵是贵，但绝对值小到不值得为它纠结——一次返工的 token 都比这个差价多。

真正拉开差距的是 agent 场景。在 dsh 里跑一个中等复杂度的任务，agent loop 几十轮循环，每轮都重发上下文——按累计输入 50 万 tokens（其中 40 万缓存命中）、输出 5 万估算：

| 时段 | V4-Flash | V4-Pro |
| --- | --- | --- |
| 空闲 | 0.40 元 | 1.19 元 |
| 高峰 | 0.79 元 | 2.37 元 |

单任务差 3 倍。一天跑 20 个任务，一个月下来两个模型的差距接近 500 块；批量跑评测、跑数据清洗的团队，这个差距直接乘上去。

这里还藏着两个省钱杠杆。一是 agent loop 每轮都重发前文，缓存命中率极高，"把稳定的系统提示词和参考资料放在输入最前面"这种缓存友好编排，比选哪个模型更影响账单。二是峰谷规则对 agent 用户格外友好：批处理任务本来就适合挂半夜，直接半价——和"半夜跑 CI"的运维习惯正好是同一件事。

## 所以，怎么选

四条实战建议：

1. **事实敏感的内容用 Pro。** 要引用版本号、命令、价格的技术长文，Pro 那种"连 rc 后缀都要解释一句"的劲儿正是你要的。用它仍然要抽查，但它编造的概率肉眼可见地低。
2. **初稿和社交内容用 Flash。** 比喻能力不输，速度快，价格三分之一。发之前记得人工过一遍数字和专名。
3. **批量任务用 Flash + 空闲时段。** 两个折扣叠加，单任务成本能压到 Pro 高峰价的六分之一。
4. **让便宜的写、让贵的审。** Flash 出初稿、Pro 做事实核查和结构打磨——这个组合比单押任何一个模型的效果都好。

至于 dsh 本身——它还是 0.1.0-rc.6 的开发者预览版，官方把丑话写在了 README 顶部：会有破坏兼容性的改动。拿它学架构、写插件没问题，生产环境再等等。
